## 0. 术语

- **concept 目标**：形如 `C t` 的命题，`C` 是一个 concept 的谓词，`t` 是**结构项**。
- **结构项的头**：结构项最外层的那个常量或变量。`sub.group G H` 的头是 `sub.group`，`G` 的头是 `G`。只看头，不看参数。
- **规则**：intro table 里的一个条目；结论是一个 concept 目标。不带前提的规则也叫事实。construction rule 不在其中（4.1）。
- **concept 前提**：规则的前提里形如 `C' t'` 的那些。**非 concept 条件**：规则的其余前提。
  - 2026-11-23 起，外面包着 `⋀`、`⟹` 的也算：前提 `⋀xs. H₁ ⟹ … ⟹ Hₙ ⟹ C' t'` 是 concept 前提，只要 `H₁ … Hₙ` 里没有一条的结论是 concept fact
    （例：`Q ?x ⟹ group ?x`、`⋀i. group (?G i)`）。有的话它整条是非 concept 条件（例：`⋀H. group H ⟹ group (?f H)`）。怎样闭合它、为什么这样分，见 4.1。
- **带条件的规则**：有非 concept 条件的规则。只有 concept 前提的规则不算带条件。
  作者 11-20 04:21：「注意一点，我上面说的“带条件”指的是带有非 concept 条件」。
  截断等式带的 `concept (…)` 条件是另一回事，本文件里总写作"带 `concept` 条件"。
- **可用的规则**：对一个 concept 目标，按第 3 节取出的那些规则。
  本文件不用"候选"这个词：B 区 7.1 里它专指 trigger 交给 Sledgehammer 的 `candidate`，公共文件的术语表里它又指 dynamic notation table 的记录
  （2026-11-22 起 dynamic notation table 不再有，由 contextual notation table 取代，D 区文件 6.3；D 区 6.4 仍用 candidate 指查一个 key 查到的条目）。
- **intro table**：`concept_fact` 查的那张表，形状见 2.1。
- **`concept_entailment`**【名字已定，见 2.2】：每个 concept 一张，记它蕴含哪些祖先 concept、各隔多远。
- **concept 距离**（记作 `d'`）：一条规则结论里的 concept 到目标的 concept 隔多远，从 `concept_entailment` 读出；就是同一个 concept 时为 0，目标的 concept 是它的 parent 时为 1。
  结构项是实例造的时，实例所声明的 concept 及其祖先之间的层数不计（4.2，11-21）。
- **leap**：用一条规则这一步让它下面的东西离目标远了几格，见 4.2。这个词出自作者 11-20 07:37。
- **安全的规则**、**不安全的规则**：条目上的一个标记，见 2.3。
- **实例自己的规则**：定义这个实例常量的那次 `concept_instance` 声明登记的规则。
- **family**、**截断**（`P.truncate t`）、**construction rule**、**selector Simpset**、**统一规则**（`C (P.truncate t) ⟷ C t`）：照各区文件的定义。
- **truncate congruence rule**：见 `CONCEPT_TRUNCATE_CONG_PLAN.md`。
- **相连的键**：由 `where super = t` 连起来的两个键，见 2.5。
- **目标的距离**、**目标的规则数**、**生效距离**：见 4.2。**方案的距离**就是生效距离，一个数。
- **方案**：顶层的 concept 目标的一棵推导，其中每条 concept 前提都已闭合；可以留下非 concept 条件。
- **解法**：搜索中某一个目标（不一定是顶层的）的一棵这样的推导，存在解法表里那个目标的条目上。
  **解法自己的生效距离**：这个解法里面各条带条件的规则加出来的那部分生效距离，不含它上面的。
- **第一个走完的方案**：搜索中第一个把待办的项全部做完的分支给出的方案（4.3）。按队列的次序，它的生效距离最小。
- **打平的解法**：同一个条目上，自己的生效距离与这个条目的第一个解法相同的另一个解法。**打平的方案**：生效距离与第一个走完的方案相同的方案。
- **记下**一个打平的解法：搜索中把它挂到它的条目上。**收进结果**：决定最后交给用户的结果里用它。记下的不一定收进（4.3"收齐打平的解法"）。
- **搜索分支**、**解法表**、**不留条件的解法的表**：见 4.3。

## 1. 本质与来由

**本质**：
- `concept_fact` 证 `C t` 时，在所有"concept 前提全部闭合"的方案里取生效距离最小的；找不到就失败。
  最小的有几个而生效距离大于 0 时，它们留下的条件用"或"连起来交给用户（一处例外见 4.2：某个目标上彼此等价的解法只取一个）。
- 每条规则只存一次。一条规则能不能用在目标上、离目标多远，从 `concept_entailment` 里查，不在登记时预先铺开，也不在查的时候沿图去走。
- 同一个 family 的实例之间、由 `where super = t` 连起来的实例之间，靠截断互相转换，这一步做在匹配里（`t` 是实例自己的参数时，在查表时补，2.5 末尾）。
- 方案的距离就是生效距离：留下的条件离要证的目标隔了几个 leap，各条带条件的规则加起来。
  leap 有三个来源：规则证的 concept 比目标强了几层；规则不安全（前提只是充分的）再加一个；
  规则是靠转换搬到另一个结构项上用的、而由目标的结构项合法推不出规则的结构项合法时，至少一个（2026-11-21 加）。
  系统标安全的规则（实例自己的规则、视图的规则、通过了声明时的判断的激活条目），在由目标的结构项合法推得出规则的结构项合法时（照原样对上的总是），leap 是 0，目标的 concept 弱几层都一样：
  它的前提只要求规则的结构项是合法的结构，而目标蕴含这一点（4.2）。
  不留任何条件的方案总是最先。
- `concept_fact` 认一条规则的结论与目标是不是同一个命题，只用 selector Simpset 的等式（E-matching up to the selector Simpset，3.2）：
  目标取出来时化简，规则在登记或激活时化简，之后只比写法，外加靠截断转换。带前提的规则都有名字，对不上时用户可以按名字手动用。
- concept 的 header 里说别的结构的假设，不作为规则进 intro table，而是在一条 concept fact 进表时激活：把它实例化、化简后的结果直接存进表（2.1 第六类）。
- 搜索是一个按生效距离排的队列，加一张"每个目标的最经济解法"的表；同一个目标在同一个距离上只解一次。搜索靠两个可配置的上限保证会停。
- `concept_fact` 从不构造。construction rule 只归 `concept_instance` 证义务的阶段一（C 区 5.1），那个流程本文件不改。

### 2.2 `concept_entailment`

**做法**【已定】。作者 13:23 提过每个实例常量建一张图的办法（第 8 节）；concept A1 提了下面这个更简单的做法，作者 13:49：「好的！我赞同你的更简单的方案！」
**名字**【已定】：作者同一条消息「给这个表起个名字吧？我提议 concept_entailment 你觉得如何？」，concept A1 赞同。

每个 concept 一张表，列出它的每个祖先，每一行三样东西（第三样 `path` 是 11-21 加的）：

```ML
concept_entailment:  {distance: int, entailment: thm, path: Thm_Name.T list option} Symtab.table Symtab.table
                     (* 外层的键是 concept，内层的键是它的祖先；
                        path 是所取那条路径上各条 parent 规则的名字，按先后；有一步没有名字时是 NONE *)
```

`path` 里每一项的类型【2026-11-23 改，`concept_package.ML` 第四次评审的 Q1，判给维护者】：是 Isabelle 的 `Thm_Name.T`（fact 的名字加第几条，只有一条时是 0），不再是字符串。
一条假设名下可以写几个命题，其中某一条形如 `D \<S>` 时，这一步的规则是那个 fact 的第 i 条定理，`Thm_Name.T` 正好说这件事；要印成用户能写的名字（`C.a(2)`）用 `Thm_Name.print`。

例，`ocg` 的那一张：

| 祖先 | concept 距离 | 蕴含 |
|---|---|---|
| `comm_group` | 1 | `ocg ?S ⟹ comm_group ?S` |
| `group` | 2 | `ocg ?S ⟹ group ?S` |
| `monoid` | 3 | `ocg ?S ⟹ monoid ?S` |
| … | | |

- **单位**【已定，作者 11-20 02:23】：concept 之间走一步是 1。「距离的单位回到 1，不再乘以 10」。
- "蕴含"一栏是沿最短路径把 parent 规则接起来得到的定理，声明 concept 时证一次。
- **怎么算**【实现】：声明 concept 时，把各个 parent 的表拿来，concept 距离加 1，蕴含前面接上自己到这个 parent 的 parent 规则。
  有菱形时（header 里写 `assumes x: "D \<S>"` 会让一个 concept 多出一条通向 `D` 的蕴含），同一个祖先有几条路：留 concept 距离小的；一样时按一个固定的次序取，保证每次相同。
- **不用更新**：新的 concept 只会作为新的末梢加进来，已有 concept 的祖先不变。
- **怎么用**：规则的结论 concept 是 `N`、目标的是 `C`。`N` 就是 `C` 时 concept 距离为 0；否则在 `N` 的表里查 `C`：查到，这条规则能用，concept 距离和蕴含一并拿到；查不到，不能用。
- 表里另存这条路径上各条 parent 规则的名字（`path`），算表时一并填【concept A1 定，11-21 02:00；concept B 检查本文件时提的】。
  `name_of` 靠它把跨了几层 concept 的一步写成 OF 链，如 `group.monoid[OF ordered_group.group[OF a]]`；路径上有一步没有名字时（如通往 base `concept` 的那条边）`path` 是 `NONE`，用后备写法。
  为什么要存：最常见的推导（`monoid G` 由 `group G`）都要跨层；作者 2026-11-18 定过后备 attribute 只作后备，B 区 7.1 的实测里后备写法比 OF 链慢 16 到 23 倍。

### 4.4 几种身份

- **proof method `concept_fact`**：证掉 concept 子目标，把方案留下的非 concept 条件作为子目标交给用户；找不到方案就失败。
  生效距离大于 0 而有几个打平的方案时，交给用户的子目标里会有"或"（4.2"取到什么"）。
  处理子目标的 `⟹` 前提的那一层照 B 区 7.1：固定参数，把前提 `Thm.assume` 进这一次调用专用的表，搜索，再 discharge。
- **simproc**：照旧只用 `concept_fact`。它交回的是带条件的改写 `R₁ ⟹ … ⟹ Rᵣ ⟹ (C t ≡ True)`，各个 `Rᵢ` 由外面的 simp 去证（B 区 7.1）。
  结果带"或"时，那个"或"就是其中一个 `Rᵢ`；`by simp` 与 `by concept_fact` 因此仍然一致。
- **只接受"不留条件的推导"的调用方**（B 区 7.1：selector simproc 消条件的第 1 步、针对 `concept _` 的 simproc）：
  跑同一个搜索，但从不展开带条件的规则【实现】。这样留下的恰好是不留条件的方案；它们从不收集打平的解法，也不化简条件。

### 4.5 例子

1. **`comm_group int.group`**。family `int` 里声明过 `int.group` 与 `int.ocg`。
   键 `int` 下有两条事实：`group int.group`、`ocg int.ocg`。前一条的 concept 不是 `comm_group` 或其后代，去掉。
   后一条的 concept `ocg` 是 `comm_group` 的后代；结构项靠截断转换：`group.truncate int.ocg = int.group`，等式不带 `concept` 条件，转得成。
   它不带前提，不留条件，生效距离是 0。
2. **`noetherian_ring real.field`**。family `real` 里有 `real.ring`、`real.field`，另有事实 `noetherian_ring real.ring`。
   结构项靠 `ring.truncate real.field = real.ring` 转过来，不留条件。
   **这个例子要等视图常量有了 truncate congruence rule 才成立**（3.2 (a)、6.2 第 8 项）。
3. **`comm_group (sub.group G H)`，两条规则都对得上**。
   一条是用户用 `[concept_intro]` 登记的 `comm_group ?G ⟹ 封闭性条件 ⟹ comm_group (sub.group ?G ?H)`，不安全，concept 正好。
   另一条是 `sub.ocg` 的规则 `ocg ?G ⟹ 封闭性条件 ⟹ 序凸 ⟹ ocg (sub.ocg ?G ?H)` 靠截断转过来的，concept 离目标一层；由 `sub.group G H` 合法推不出 `sub.ocg G H` 合法，leap 是 `max(d', 1)`，这里就是 `d'`。
   - 上下文里有 `ocg G`：前一条不安全、`d'` 是 0，leap 是 1，生效距离 1；后一条安全、`d'` 是 1，leap 是 1，生效距离也是 1。两者打平。
     结果是 `封闭 ∨ (封闭 ∧ 序凸)`，整理成"封闭"。`G` 是整数、`H` 是偶数时"序凸"是假的，"封闭"证得出。
     这个例子是没有采用"按不安全规则的使用次数再分先后"的主要依据：那样后一条会单独胜出，留下假的"封闭 ∧ 序凸"（第 8 节）。
   - 没有用户那一条、上下文里有 `ocg G`：只有后一条，生效距离 1。
   - 上下文里只有 `comm_group G`：后一条的前提 `ocg G` 闭合不了；有用户那一条就用它，没有就失败。
4. **`group (sub.group G H)`，上下文里有 `group G`**。
   `sub.group` 自己的规则用在自己这个实例上，leap 是 0，生效距离 0。用户另用 `[concept_intro]` 登记的一条条件不同的规则：leap 是 1，生效距离 1。取实例自己的，搜索到此停止。

5. **不留条件的方案总是最先**。目标 `monoid (f (g X))`，有两个方案：
   用 `monoid ?A ⟹ monoid (f ?A)`、`monoid ?A ⟹ monoid (g ?A)` 与事实 `monoid X` 证完，不留条件；
   用 `cond ?A ⟹ monoid (f ?A)` 一步、留下 `cond (g X)`：这条规则不安全时生效距离是 1；安全时也是 0，但带条件规则的个数是 1。

6. **concept 离得远的规则排在后面**。目标 `ring (zmod n)`，上下文里有 `1 < n`。
